# via 0.3.10

via 0.3.10 makes route estimates more realistic and keeps the graph flexible without making the Skill heavier.

## Estimate one useful step

Token and time ranges now share one boundary: route selection to the next useful engineering deliverable.

- Tokens describe incremental model workload across context reads, tool feedback, reasoning, and output.
- Minutes describe active agent wall-clock across inspection, edits, tools, and verification.
- Human approval, deployment queues, observation windows, and team calendar time stay outside the cards.

The guidance uses broad evidence-aware ranges instead of provider pricing or model multiplier tables.

## Let topology follow the task

Most maps still share one start and finish. When the task naturally presents more than one available origin or useful outcome, routes can share any subset of terminal nodes. This supports two starts leading to one result, one start leading to several results, or fully separate paths without adding a user-facing mode.

The runtime prompt is shorter: map work as it naturally overlaps, diverges, and converges. Detailed graph capabilities remain in RouteSpec and tests rather than burdening every invocation.

## Model fit

README now gives one behavioral threshold: the model-agent setup should inspect a repository, form three materially distinct routes from an ambiguous task, and emit valid RouteSpec with at most one small repair.

The deeper research remains outside the runtime Skill and includes representative candidates from OpenAI, Anthropic, Google, Moonshot AI, DeepSeek, Alibaba Qwen, and Z.ai. Inclusion is a test candidate, not certification or a leaderboard.
